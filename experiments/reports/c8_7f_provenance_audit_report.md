## 5. Discrepancy Classification (Task 4)

This discrepancy is classified as:
* **Category C (Evaluation / Protocol & Terminology Semantic Correction):** The earlier script named its baseline condition `C0_Baseline`, but in reality, that condition was NOT pure strapdown IMU dead reckoning. It was an undocumented combination of strapdown IMU + un-frozen NHC + ZUPT. When Stage C8-7D created a clean, modular ablation matrix, it properly defined `A0_Baseline_PureIMU` as true pure strapdown dead reckoning (zero constraints).
* **Category B (Accidental Implementation Detail):** In `C0_Baseline`, applying `nhc.update_eskf` without forward speed updates and without bias freezing actually *worsened* early-horizon drift on `Vta02` compared to pure strapdown double integration. Pure inertial propagation with ground-truth velocity initialization $\mathbf{v}_0$ on gentle suburban straights drifts only $\sim 10\text{ m}$ at 5s, whereas the un-frozen NHC distorted the velocity vector on vehicle maneuvers.

## 8. Benchmark Validity vs Real-World Validity (Task 7)

To preserve scientific rigor, the following operational boundaries must be documented:
1. **Ground Truth Initialization:** The current benchmark initializes position, velocity, and heading at blackout onset ($t=0$) using VBOX GNSS/INS ground truth. It evaluates blackout dead reckoning, not cold-start position fixing.
2. **Pre-Aligned Phone Mounting:** The benchmark operates with $\mathbf{R}_{vp} = \mathbf{I}_{3\times 3}$. It does not yet evaluate in-motion automatic sensor-to-vehicle alignment or loose phone placement.
3. **Sample Size Limitations:**
   - On `Vta04`, the 60s horizon has $N=1$ window (an on-ramp curve). It is a single stress test, not a statistical ensemble.
   - On `Vta02`, the 60s horizon has $N=17$ windows across varied road regimes.
4. **Causal Quarantine:** Ground truth is strictly restricted to epoch $t=0$ initialization and post-window error residual evaluation. Zero ground truth or CAN data enters smartphone estimation.
